# basic-setup

[![Deploy admin_init.sh to GitHub Pages](https://github.com/anshibanov/basic-setup/actions/workflows/ci.yml/badge.svg)](https://github.com/anshibanov/basic-setup/actions/workflows/ci.yml)

Скрипт первичной настройки Linux-сервера: создание привилегированного пользователя `admin_init` с SSH-доступом по ключам, отключение парольной аутентификации и уведомление через [ntfy.sh](https://ntfy.sh).

## Быстрый старт

Выполните на новом сервере от имени root:

```bash
curl -sSL https://anshibanov.github.io/basic-setup/admin_init.sh | sudo bash
```

Скрипт развёрнут через GitHub Pages и доступен по прямой ссылке.

## Что делает скрипт

1. **Устанавливает sudo**, если его нет (Proxmox VE и минимальный Debian поставляются без него)
2. **Создаёт пользователей** `admin_init`, `orange` и `byak` со случайно сгенерированными паролями
3. **Настраивает sudo** — беспарольный доступ через `/etc/sudoers.d/` для всех трёх пользователей
4. **Устанавливает SSH-ключи** — ведёт управляемый блок в `authorized_keys` этих пользователей (и пользователя `ubuntu`, если он существует) и удаляет отозванные ключи
5. **Обнаруживает Proxmox VE** — если сервер работает на Proxmox, добавляет `admin_init` с ролью Administrator в PVE
6. **Отключает парольную аутентификацию SSH** — оставляет только вход по ключам
7. **Шифрует пароль** `admin_init` с помощью [Age](https://age-encryption.org) и отправляет уведомление на ntfy.sh с информацией о сервере
8. **Сообщает о сбое** — если настройка прервалась, на ntfy.sh уходит уведомление с шагом и кодом выхода

## Требования

Скрипт рассчитан на Debian/Ubuntu. Необходимые пакеты:

| Пакет | Назначение |
|-------|------------|
| `openssl` | Генерация и хеширование пароля |
| `sudo` | Настройка привилегий (скрипт установит сам, если пакета нет) |
| `curl` | Определение внешнего IP, отправка уведомлений |
| `iproute2` | Определение внутреннего IP (команда `ip`) |
| `openssh-server` | SSH-сервер |
| `age` | Шифрование пароля (опционально — скрипт попытается установить автоматически) |

## Шифрование пароля

Сгенерированный пароль шифруется с помощью [Age](https://age-encryption.org) перед отправкой через ntfy.sh.

- Если `age` не установлен — скрипт попытается установить его автоматически
- Если установка не удалась — пароль не отправляется, в уведомление добавляется предупреждение
- В любом случае пароль сохраняется на сервере в `/root/.admin_init_password.txt`
- Пароль отправляется, пока ntfy.sh не примет его шифртекст: если первый запуск сорвался или уведомление не дошло, пароль уйдёт при следующем успешном запуске. Факт доставки отмечается файлом `/root/.admin_init_password.sent`

Подробная инструкция по расшифровке: **[DECRYPT.md](DECRYPT.md)**

### Быстрая расшифровка

В уведомлении приходит только зашифрованный блок, без готовой команды. Скопируйте блок и передайте его в `age`:

```bash
pbpaste | age -d -i ~/.age/key.txt        # macOS
wl-paste | age -d -i ~/.age/key.txt       # Linux (Wayland)
```

Топик ntfy.sh публичный, и отправить в него сообщение может кто угодно. Никогда не выполняйте команды, пришедшие в уведомлении.

## Отзыв SSH-ключей

Ключи из `SSH_KEYS` записываются в управляемый блок файла `authorized_keys`:

```
# BEGIN admin_init managed keys
ssh-ed25519 AAAA... admin_init
...
# END admin_init managed keys
```

Блок пересобирается при каждом запуске, остальные строки файла не трогаются. Чтобы отозвать ключ:

1. Перенесите его строку из `SSH_KEYS` в `REVOKED_SSH_KEYS` в `admin_init.sh`
2. Запустите скрипт на серверах ещё раз

Ключ из `REVOKED_SSH_KEYS` удаляется из всего файла — в том числе строки, записанные прежними версиями скрипта (до появления блока) или добавленные вручную. Если просто удалить ключ из `SSH_KEYS`, он исчезнет только из блока, а на серверах, настроенных старой версией, останется. Отзыв действует на `admin_init`, `orange`, `byak` и `ubuntu`; ключи пользователя `root` скрипт не трогает.

## CI/CD

GitHub Actions workflow (`.github/workflows/ci.yml`) выполняет:

### Тестирование

При каждом push и pull request в `main` скрипт запускается в Docker-контейнерах:

- **Debian** (`debian:12`, `debian:13`)
- **Ubuntu** (`ubuntu:24.04`, `ubuntu:26.04`)

Контейнер стартует без `sudo`: скрипт должен установить его сам, в том числе пока блокировку dpkg держит другой процесс. Тест выполняет два запуска, проверяет пользователей, sudo, ключи и сохранение паролей. Затем идут отдельные наборы:

- **Пользователи** — сбой между созданием пользователя и установкой пароля исправляется повторным запуском
- **SSH-ключи** — управляемый блок, перенос ключей из старого формата, отзыв, файл без завершающего перевода строки, повреждённый блок
- **Уведомления** — настоящий `curl` обращается к локальной замене ntfy.sh: шифртекст расшифровывается тестовым ключом Age в пароль учётной записи, пароль доставляется повторно после неудачной отправки, при сбое и при прерывании сигналом приходит уведомление с шагом и кодом
- **sshd** — регистр директив, отсутствие `Include`, блоки `Match`, символические ссылки, повторный запуск, откат при ошибках валидации и перезапуска и при сигнале, отказ отключать пароли, если вход по ключам не работает. Проверяется также соединение с запущенным sshd

В основном прогоне `curl` заменён заглушкой, в тесте уведомлений адреса сервисов подменены локальными: настоящие уведомления ntfy.sh не отправляются.

Отдельные задания проверяют настоящий systemd как PID 1: обычный запуск `ssh.service` и активацию через `ssh.socket` на всех четырёх ОС. Проверяется реальный вход по ключу и отсутствие парольных методов у работающего сервера.

Проверка Proxmox 9 использует официальные подписанные пакеты `pveum` и `pmxcfs` в локальном режиме. Она проверяет создание PAM-пользователя, точное совпадение userid, роль Administrator на `/`, эффективные права, повторный запуск и сохранение настроек после перезапуска `pmxcfs`. Ошибки команд проверяются отдельно с подменой результата команды. Второй тест выполняет скрипт целиком на том же образе без `sudo` и `age`, как на свежем узле PVE: скрипт сам ставит оба пакета, создаёт пользователей и выдаёт права. Загрузка полноценного узла PVE, работа виртуальных машин и веб-интерфейс в эти тесты не входят.

## Локальное тестирование

`sudo` в список пакетов не входит намеренно: тест проверяет, что скрипт ставит его сам.

```bash
# Тест на Debian (также debian:12)
docker run --rm -v "$(pwd)":/app:ro -w /app debian:13 bash -c "\
  apt-get -qq update > /dev/null && \
  apt-get -qq install -y openssl curl iproute2 openssh-server age > /dev/null && \
  bash ./tests/container-test.sh"

# Тест на Ubuntu (также ubuntu:24.04)
docker run --rm -v "$(pwd)":/app:ro -w /app ubuntu:26.04 bash -c "\
  apt-get -qq update > /dev/null && \
  apt-get -qq install -y openssl curl iproute2 openssh-server age > /dev/null && \
  bash ./tests/container-test.sh"
```

Проверки systemd и Proxmox запускайте только в одноразовых контейнерах; для systemd нужны записываемые cgroup, а для `pmxcfs` — FUSE. Команды используют `--privileged`, отдельные сетевые пространства и монтируют исходники только для чтения:

```bash
docker build --build-arg BASE=debian:13 -f tests/systemd.Dockerfile -t basic-setup-systemd:test .
bash tests/systemd-test.sh basic-setup-systemd:test

docker build -f tests/proxmox.Dockerfile -t basic-setup-proxmox:test .
docker run --rm --privileged --cgroupns private --network none \
  --hostname basic-setup-pve-validation \
  -v "$(pwd):/app:ro" -w /app \
  basic-setup-proxmox:test bash tests/proxmox-test.sh

# Полный прогон скрипта: нужна сеть, скрипт ставит sudo и age
docker run --rm --privileged --cgroupns private \
  --hostname basic-setup-pve-validation \
  -v "$(pwd):/app:ro" -w /app \
  basic-setup-proxmox:test bash tests/proxmox-main-test.sh
```

## Безопасность

- Пароль шифруется Age-шифрованием перед отправкой через ntfy.sh; в уведомлении только шифртекст, без команд для терминала
- Топик ntfy.sh публичный: уведомления (IP-адреса, имя хоста, ОС) может прочитать любой, кто знает топик, и любой может отправить в него своё сообщение. Закрыть чтение можно только на стороне ntfy — зарезервировать топик с правом «остальные только публикуют» или использовать свой сервер
- SSH парольная аутентификация отключается автоматически
- Пароли не отключаются, если после этого на сервер нельзя было бы войти: `sshd` должен принимать ключи (`PubkeyAuthentication yes`) и читать `~/.ssh/authorized_keys`
- Настройки добавляются в начало основного конфига, вне `Match` и до `Include`; регистр существующих директив учитывается
- Поддерживаются основной конфиг `/etc/ssh/sshd_config` и файлы `/etc/ssh/sshd_config.d/*.conf`; парольные исключения в `Match`, подключённых из других путей, требуют отдельной проверки и изменения
- Проверяются синтаксис (`sshd -t`) и итоговые настройки (`sshd -T`); при ошибке валидации или перезапуска, а также при прерывании (Ctrl-C, обрыв сессии) исходные файлы восстанавливаются
- Отозванные SSH-ключи удаляются при повторном запуске (см. «Отзыв SSH-ключей»)
- Файл пароля на сервере доступен только root (`chmod 600`)
- Скрипт идемпотентен — безопасен при повторном запуске

## Особенности работы

- Скрипт использует `set -e` — при ошибке в критических операциях выполнение прекращается
- Ошибка настройки или перезапуска SSH завершает скрипт с ненулевым кодом; уведомление об успехе не отправляется
- При любом сбое или прерывании на ntfy.sh уходит уведомление «Server Setup FAILED» с высоким приоритетом: шаг, код выхода и сведения о сервере
- Пользователь, оставшийся без пароля после прерванного запуска, получает пароль при следующем запуске
- Некритические операции (уведомления, шифрование) обёрнуты в обработку ошибок и не прерывают работу скрипта
- При обнаружении Proxmox VE пользователь автоматически добавляется в PVE с ролью Administrator
- Если на сервере есть пользователь `ubuntu`, SSH-ключи добавляются и ему
